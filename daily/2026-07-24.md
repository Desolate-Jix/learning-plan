## 1. 自己最终 Accepted 的代码

```java
class Solution {
    public int[] productExceptSelf(int[] nums) {
        int k = nums.length;
        int[] answer = new int[k];
        int left = 1;
        int right = 1;

        answer[0] = 1;

        for (int i = 1; i < k; i++) {
            left = left * nums[i - 1];
            answer[i] = left;
        }

        for (int i = k - 2; i >= 0; i--) {
            right = right * nums[i + 1];
            answer[i] = answer[i] * right;
        }

        return answer;
    }
}
```

> 上面只统一了缩进和空格，保留实际提交通过的算法结构。

## 2. 核心公式

对于每个位置 `i`：

```text
answer[i]
=
i 左边所有数字的乘积
×
i 右边所有数字的乘积
```

例如：

```text
nums = [1, 2, 3, 4]
```

答案：

```text
[24, 12, 8, 6]
```

因为：

```text
下标 0：2 × 3 × 4 = 24
下标 1：1 × 3 × 4 = 12
下标 2：1 × 2 × 4 = 8
下标 3：1 × 2 × 3 = 6
```

## 3. 第一遍：把左边乘积写进 `answer`

初始：

```java
answer[0] = 1;
```

下标 `0` 左边没有元素。乘法中的空乘积取 `1`，因为：

```text
1 × x = x
```

递推关系：

```text
当前位置的左乘积
=
上一位置的左乘积
×
上一位置的原数组元素
```

代码：

```java
for (int i = 1; i < k; i++) {
    left = left * nums[i - 1];
    answer[i] = left;
}
```

对于 `[1,2,3,4]`，第一遍后：

```text
answer = [1, 1, 2, 6]
```

逐步过程：

| `i` | 上一元素 `nums[i-1]` | 更新后的 `left` | `answer[i]` |
|---:|---:|---:|---:|
| 1 | 1 | `1 × 1 = 1` | 1 |
| 2 | 2 | `1 × 2 = 2` | 2 |
| 3 | 3 | `2 × 3 = 6` | 6 |

此时 `answer[i]` 只保存当前位置左侧所有元素的乘积。

## 4. 第二遍：从右向左补上右边乘积

自己写出的右侧循环：

```java
for (int i = k - 2; i >= 0; i--) {
    right = right * nums[i + 1];
    answer[i] = answer[i] * right;
}
```

这里从 `k - 2` 开始，而不是从最后一位开始，原因是：

- 最后一位右边没有元素；
- 它的右乘积是 `1`；
- 第一遍得到的 `answer[k - 1]` 已经就是最终答案，无需再次修改。

对于 `[1,2,3,4]`：

| `i` | 新加入右侧的元素 | 更新后的 `right` | 原左乘积 | 最终 `answer[i]` |
|---:|---:|---:|---:|---:|
| 2 | `nums[3] = 4` | 4 | 2 | `2 × 4 = 8` |
| 1 | `nums[2] = 3` | 12 | 1 | `1 × 12 = 12` |
| 0 | `nums[1] = 2` | 24 | 1 | `1 × 24 = 24` |

最终：

```text
[24, 12, 8, 6]
```

### 为什么使用 `nums[i + 1]`

当前答案不能包含 `nums[i]` 自己。因此从右向左时，只把当前位置右边的下一个元素加入 `right`：

```java
right = right * nums[i + 1];
```

更新后，`right` 恰好表示：

```text
nums[i + 1] × nums[i + 2] × ... × nums[k - 1]
```

也就是当前位置右边所有元素的乘积。

## 5. 自己推导出的关键理解

今天自己总结：

> 维护左边和右边乘积，不需要再次计算上次之前的乘积，直接复用上一轮结果。

更准确地写成：

```text
新的累计乘积
=
上一轮累计乘积
×
本轮新增的一个元素
```

左边：

```text
leftProduct(i)
=
leftProduct(i - 1) × nums[i - 1]
```

右边：

```text
rightProduct(i)
=
rightProduct(i + 1) × nums[i + 1]
```

这就是**状态复用**：保存已经计算好的信息，下一步只处理新增部分，而不是每个下标都从头计算。

同样的思想以后会出现在：

- 前缀和；
- 前缀乘积；
- 滑动窗口；
- 动态规划；
- 前缀异或。

## 6. 为什么复杂度从 `O(n²)` 降到 `O(n)`

### 暴力法

对每个下标，都重新遍历其他元素并相乘：

```text
n 个位置
×
每个位置约 n 次乘法
=
O(n²)
```

同一段乘积会被反复计算。

### 当前优化法

- 第一遍从左到右：`O(n)`；
- 第二遍从右到左：`O(n)`。

总计：

```text
O(n) + O(n) = O(2n) = O(n)
```

每个元素只被处理常数次。

## 7. 为什么不使用除法

题目禁止除法。即使题目允许，数组中出现 `0` 时也会产生问题：

- 无法执行除以 `0`；
- 一个或多个 `0` 会改变每个位置答案的判断方式。

前缀乘积和后缀乘积不依赖除法，能够自然处理 `0`。

---

## 8. 空乘积为什么是 `1`

在乘法中，`1` 是单位元：

```text
1 × x = x
```

因此：

- 第一个元素左边没有数字，左乘积为 `1`；
- 最后一个元素右边没有数字，右乘积为 `1`。

如果使用默认值 `0`：

```text
0 × 任何数 = 0
```

所有后续乘积都会被破坏。

### 可以改进的地方

变量名可以更清楚：

```java
int n = nums.length;
int leftProduct = 1;
int rightProduct = 1;
```

第一遍也可以直接使用输出数组的递推关系，不单独维护 `left`：

```java
answer[0] = 1;
for (int i = 1; i < n; i++) {
    answer[i] = answer[i - 1] * nums[i - 1];

```

常见的另一种右侧写法是：

```java
int rightProduct = 1;
for (int i = n - 1; i >= 0; i--) {
    answer[i] *= rightProduct;
    rightProduct *= nums[i];
}
```

这和自己的写法本质相同：都保证当前位置答案不乘入 `nums[i]` 自己。
