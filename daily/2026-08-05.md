# 任务 A｜374. Guess Number Higher or Lower

[打开题目](https://leetcode.com/problems/guess-number-higher-or-lower/)

## 完成结果

- **难度：** Easy
- **结果：** Accepted，25 / 25
- **提交记录：** 0 ms、41.90 MB；单次排名仅作参考
- **主题：** 二分查找、题目提供的 API、整数溢出
- **时间复杂度：** `O(log n)`
- **额外空间：** `O(1)`
- **掌握等级：** B

### 为什么记为 B

这次能够根据 `guess(current)` 的返回结果写出左右边界收缩，但实现过程中经过了多轮提示和调试：

1. 理解 `guess(int num)` 是 LeetCode 提供的方法/API，不需要自己实现；
2. `guess(current)` 返回 `int`，不能写成 `!guess(current) == 0`，应比较 `guess(current) != 0`；
3. Java 要求所有执行路径返回 `int`，因此循环后需要兜底 `return -1`；
4. `guess(current) == 1` 表示当前值太小，应移动 `left`；返回 `-1` 表示当前值太大，应移动 `right`；
5. 边界必须使用 `current + 1` 和 `current - 1`，否则中点可能不变并形成死循环；
6. 最初使用 `(left + right) / 2`，在大整数测试上溢出并出现 TLE；改为防溢出写法后通过。

核心算法不是完全独立完成，因此暂记 B。后续闭卷重写并能主动写出防溢出中点公式后再提升等级。

## 最终 Accepted 代码

```java
public class Solution extends GuessGame {
    public int guessNumber(int n) {
        int left = 1;
        int right = n;

        while (left <= right) {
            int current = left + (right - left) / 2;
            int result = guess(current);

            if (result == 1) {
                left = current + 1;
            } else if (result == -1) {
                right = current - 1;
            } else {
                return current;
            }
        }

        return -1;
    }
}
```

## `guess()` 返回值与边界方向

```text
guess(current) == 0
→ current 就是答案

guess(current) == 1
→ current 小于隐藏数字
→ 答案在右侧
→ left = current + 1

guess(current) == -1
→ current 大于隐藏数字
→ 答案在左侧
→ right = current - 1
```

## 调试记录

### 1. `!` 不能用于整数

错误：

```java
!guess(current) == 0
```

`guess(current)` 返回的是 `int`，而 `!` 只能对 `boolean` 使用。

### 2. 边界方向与 `±1`

错误方向会把答案所在区间丢掉；不加 `1` 或减 `1` 时，`current` 可能在下一轮保持不变。

### 3. 中点整数溢出

首次可运行版本使用：

```java
int current = (left + right) / 2;
```

在以下大输入上出现：

```text
Time Limit Exceeded
14 / 25 testcases passed
n = 2126753390
pick = 1702766719
```

原因是 `left + right` 可能超过：

```text
Integer.MAX_VALUE = 2147483647
```

溢出后中点可能变成负数，区间不能正确收缩。

最终使用：

```java
int current = left + (right - left) / 2;
```

`right - left` 在合法区间内不会超过 `int` 上限，从而避免加法溢出。

## 最终 Accepted 代码

```java
class Solution {
    public boolean closeStrings(String word1, String word2) {
        Map<Character, Integer> map1 = new HashMap<>();
        Map<Character, Integer> map2 = new HashMap<>();

        map1 = loadmap(word1);
        map2 = loadmap(word2);

        if (map1.size() != map2.size()) {
            return false;
        }

        for (char c : map1.keySet()) {
            if (!map2.containsKey(c)) {
                return false;
            }
        }

        List<Integer> values1 = new ArrayList<>(map1.values());
        List<Integer> values2 = new ArrayList<>(map2.values());

        Collections.sort(values1);
        Collections.sort(values2);

        return values1.equals(values2);
    }

    public Map loadmap(String word) {
        int n = word.length();
        Map<Character, Integer> map = new HashMap<>();

        for (int i = 0; i < n; i++) {
            map.put(
                word.charAt(i),
                map.getOrDefault(word.charAt(i), 0) + 1
            );
        }

        return map;
    }
}
```

## 核心判断

### 条件一：字符集合相同

题目操作只能交换已有字符，不能创造一种从未出现过的新字符。因此：

```text
word1 出现过的字符集合 == word2 出现过的字符集合
```

当前代码先比较 `map.size()`，再逐个使用 `containsKey()` 检查。

### 条件二：频率多重集合相同

例如：

```text
word1 = "aabbb" → {a=2, b=3}
word2 = "aaabb" → {a=3, b=2}
```

字符集合相同，频率排序后都是：

```text
[2, 3]
```

所以可以通过交换字母角色互相转换。

## 调试记录

### `getOrDefault()` 使用了错误的 key

错误写法：

```java
map.put(word.charAt(i), map.getOrDefault(i, 0) + 1);
```

写入使用的是字符 `word.charAt(i)`，查询旧次数却使用了下标 `i`。两边 key 类型和含义不一致，导致重复字符始终被统计为 `1`。

修复为：

```java
char c = word.charAt(i);
map.put(c, map.getOrDefault(c, 0) + 1);
```

### 为什么不能用 HashSet 保存频率

频率需要保留重复次数。例如：

```text
[1, 1, 2]
[1, 2, 2]
```

转成 Set 后都会变成 `{1, 2}`，会丢失信息。因此应使用 List 排序后比较。

## Reviewer 点评

当前解法正确。辅助方法最好补全泛型，避免 raw type：

```java
private Map<Character, Integer> loadMap(String word)
```

方法名也推荐使用 Java 的 camelCase：`loadMap`，而不是 `loadmap`。
