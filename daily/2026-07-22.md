## 任务 1｜Easy 热身

[1071. Greatest Common Divisor of Strings](https://leetcode.com/problems/greatest-common-divisor-of-strings/)

- **中文：** 字符串的最大公因子
- **白名单位置：** Array / String 第 2 题
- **预计时间：** 25～35 分钟

### 先理解题目

如果一个字符串可以重复若干次组成另一个字符串，那么它就是另一个字符串的“因子”。

例如：

```text
"ABC" 重复 2 次 = "ABCABC"
```

所以：

```text
str1 = "ABCABC"
str2 = "ABC"
答案 = "ABC"
```

另一个例子：

```text
str1 = "ABABAB"
str2 = "ABAB"
答案 = "AB"
```

今天要思考：

1. 两个字符串是否由同一个最小重复单位组成；
2. 候选字符串长度为什么必须同时整除两个字符串长度；
3. 如果没有共同重复单位，为什么返回空字符串 `""`。

### 今天可能用到的 Java

```java
str.length()
str.substring(start, end)
str1.equals(str2)
length % candidateLength
```

特别注意：比较字符串内容使用：

```java

```

不要使用：

```java

```

## 任务 2｜Medium 主任务

[238. Product of Array Except Self](https://leetcode.com/problems/product-of-array-except-self/)

- **中文：** 除自身以外数组的乘积
- **白名单位置：** Array / String 第 7 题
- **预计时间：** 60～80 分钟

### 题目目标

例如：

```text
nums = [1, 2, 3, 4]
```

输出：

```text
[24, 12, 8, 6]
```

因为：

```text
下标 0：2 × 3 × 4 = 24
下标 1：1 × 3 × 4 = 12
下标 2：1 × 2 × 4 = 8
下标 3：1 × 2 × 3 = 6
```

### 今天要理解的核心

对每个下标 `i`：

```text
answer[i] = i 左边所有数的乘积 × i 右边所有数的乘积
```

它和 Pivot Index 的思想相似：

```text
整体被拆成：左边 + 当前 + 右边
```

这题把加法换成乘法：

```text
结果 = 左边乘积 × 右边乘积
```

题目不允许使用除法，因此不能先算总乘积再除以 `nums[i]`。

### 建议思考顺序

1. 先尝试暴力：对每个 `i` 重新乘其他元素，理解为什么是 `O(n²)`；
2. 再想能否提前保存每个位置左边的乘积；
3. 从右向左维护一个 `rightProduct`；
4. 把左边结果与右边乘积相乘。

今天先理解，不要求一开始就写出最省空间版本。

## 当前反馈｜任务 1 暂时没有思路

- **当前状态：** 尚未形成代码结构；先降低难度，不直接使用“拼接判断 + 数学最大公约数”的快捷解法。
- **第一层理解：** 把答案看成一个可以反复铺满两个字符串的“最长积木”。

### 从例子推导

```text
str1 = "ABABAB"，长度 6
str2 = "ABAB"，长度 4
```

尝试候选长度：

```text
长度 4：6 不能被 4 整除，跳过
长度 3：4 不能被 3 整除，跳过
长度 2：6 和 4 都能被 2 整除
候选 = str1.substring(0, 2) = "AB"
```

再检查：

```text
"ABABAB" = "AB" + "AB" + "AB"
"ABAB"   = "AB" + "AB"
```

所以答案是 `"AB"`。

### 当前建议的解题步骤

1. 公共因子一定从两个字符串的第一个字符开始，所以候选可以取 `str1` 的前缀；
2. 候选长度必须同时整除两个字符串长度；
3. 因为要找最长答案，所以从较短字符串的长度开始向下尝试；
4. 把目标字符串每隔 `candidate.length()` 切成一块；
5. 每一块都必须与候选字符串 `.equals()`；
6. 第一组同时通过两个字符串检查的候选就是答案；全部失败则返回 `""`。

class Solution {
    public String gcdOfStrings(String str1, String str2) {
        int maxLength = Math.min(str1.length(), str2.length());

        for (int length = maxLength; length >= 1; length--) {
            if (str1.length() % length != 0
                    || str2.length() % length != 0) {
                continue;
            }

            String candidate = str1.substring(0, length);

}

## 调试记录｜`StringIndexOutOfBoundsException`

当前运行时报错：

```text
Index 3 out of bounds for length 3
```

原因在公共前缀循环的条件中：

```java
for (int i = 0; i < n1 && 1 < n2; i++)
```

第二个条件误写成了数字 `1 < n2`。只要 `n2 > 1`，这个条件会一直为 `true`，因此循环只受 `i < n1` 控制；当 `str2` 比 `str1` 短时，`i` 会到达 `str2.length()`，随后 `str2.charAt(i)` 越界。

正确边界应让 `i` 同时小于两个字符串长度：

```java
for (int i = 0; i < n1 && i < n2; i++)
```

也可以写得更直观：

```java
int limit = Math.min(n1, n2);
for (int i = 0; i < limit; i++) {
    // 比较两个字符串的第 i 个字符
}
```

另外，如果两个字符串第一个字符就不同，`candidate` 会是空字符串，后续 `n1 % candidate.length()` 会导致除以零错误。调用 `checkcandidate` 前需要先处理：

```java
if (candidate.length() == 0) {
    return "";
}
```

本轮重点：数组或字符串访问下标 `i` 前，必须保证 `i < length`；循环里同时访问两个字符串时，边界必须受较短字符串限制。

## 调试记录｜`ArithmeticException: / by zero`

测试输入：

```text
str1 = "LEET"
str2 = "CODE"
```

两个字符串第一个字符就不同，因此公共前缀循环立即 `break`，`StringBuilder` 仍为空：

```java
String candidate = sb.toString(); // ""
int k = candidate.length();       // 0
```

随后调用 `checkcandidate`，其中执行：

```java
n1 % n2
```

此时 `n2 == 0`，等价于对 0 取余，所以抛出 `/ by zero`。

应在调用 `checkcandidate` 前先处理空候选：

```java
if (candidate.length() == 0) {
    return "";
}
```

本轮还暴露出更深一层的逻辑问题：当前代码只检查“最长公共前缀”这一个候选。如果最长公共前缀不能铺满两个字符串，代码会直接返回空字符串，但更短前缀仍可能是正确答案。例如：

```text
str1 = "ABABAB"
str2 = "ABAB"
最长公共前缀 = "ABAB"，但正确答案 = "AB"
```

因此修复除零后，下一步应改为：从较短字符串长度开始向下枚举候选长度，而不是只检查完整公共前缀。
