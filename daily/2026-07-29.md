# 1004. Max Consecutive Ones III

[打开题目](https://leetcode.com/problems/max-consecutive-ones-iii/)

## 完成结果

- **难度：** Medium
- **结果：** Accepted，63 / 63
- **提交记录：** 3 ms、52.16 MB；单次排名只作参考
- **主题：** 可变长度滑动窗口
- **时间复杂度：** `O(n)`
- **额外空间：** `O(1)`
- **掌握等级：** B+

## 今天自己的思路

自己推导的是“最大窗口长度只增不减”版本：

```text
右边界每轮向右移动
未超出 k：左边界不动，窗口增长
超出 k：左边界也向右移动，窗口长度保持
```

核心判断是：

```text
超限的这一轮窗口没有增长，因此不可能刷新最大长度。
```

这个思路最终通过全部测试，说明算法不变量成立。

## 调试与实现卡点

最初实现复杂，主要因为把状态拆成：

```text
zero < k
zero == k
zero > k
```

三个分支，并在各分支分别维护：

```text
右边进入
左边离开
zero 增减
continue
```

这容易导致：

- 同一个元素被漏算或重复计算；
- `continue` 作用于错误的循环；
- `i`、`j` 移动与 `zero` 更新不同步；
- 右包含边界和循环结束后的下标含义混淆。

## 标准滑动窗口

今天理解了标准结构：

```java
class Solution {
    public int longestOnes(int[] nums, int k) {
        int left = 0;
        int zeroCount = 0;
        int maxLength = 0;

        for (int right = 0; right < nums.length; right++) {
            if (nums[right] == 0) {
                zeroCount++;
            }

            while (zeroCount > k) {
                if (nums[left] == 0) {
                    zeroCount--;
                }
                left++;
            }

            int currentLength = right - left + 1;
            maxLength = Math.max(maxLength, currentLength);
        }

        return maxLength;
    }
}
```

标准版本只维护两次局部变化：

```text
刚进入窗口的 nums[right]
刚离开窗口的 nums[left]
```

不需要重新遍历整个窗口统计 `0`。

## 为什么标准版本能覆盖所有答案

对每一个 `right`：

```text
先加入 nums[right]
窗口不合法时移动 left
恢复合法后，得到以 right 结尾的最长合法窗口
```

所有可能的右边界都会被遍历，因此全局最优窗口的右边界也一定会被处理。

最大长度必须在窗口恢复合法后更新：

```java
maxLength = Math.max(maxLength, right - left + 1);
```

## 两个版本的不变量差异

### 自己的版本

```text
允许窗口暂时非法
维护的候选窗口长度只增加或保持
最后的长度就是历史最大候选长度
```

### 标准版本

```text
每次更新答案前窗口一定合法
对每个 right 找到以它结尾的最长合法窗口
显式使用 Math.max 保存历史最大值
```
